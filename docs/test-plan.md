# Тест-план: aqa_juice_shop

## 1. Введение

Пет-проект по автоматизации тестирования веб-приложения OWASP Juice Shop.
Цель — отработка практических подходов к автоматизации: устойчивые локаторы,
негативные и позитивные сценарии, кроссбаузерное тестирование, CI-прогон на каждый push.

## 2. Объект тестирования

- Приложение: [OWASP Juice Shop](https://owasp.org/www-project-juice-shop/)
- Проверяемая функциональность: регистрация пользователя (форма /#/register)
- Окружение: локальный запуск в Docker Compose, Chromium (Playwright), headless в CI

## 3. Стратегия

- **UI-автотесты (pytest + Playwright)** — сквозные проверки через браузер.
- **Негативные и позитивные сценарии** раздельно.
- Каждый тест самодостаточен: генерирует уникальный email (uuid), не зависит от данных прошлого прогона.
- Прогон в GitHub Actions на каждый push.

## 4. Покрываемые сценарии

| ID   | Сценарий | Ожидаемый результат |
|------|----------|---------------------|
| TC-01 | Регистрация с валидными данными | Успешная регистрация, редирект на /#/login |
| TC-02 | Несовпадающие пароли | Сообщение «Passwords do not match», кнопка регистрации заблокирована |

## 5. Внеплановые (известные) риски

- Флаки из-за анимаций Material-UI (перекрытие элементов) — частично решено force-кликом.
- Зависимость от ответов на секретные вопросы (порядок в выпадающем списке).

## 6. План развития

- Проверка валидации полей формы регистрации
- UI-тесты
- API-тесты
- Моки и заглушки
- Кроссбаузерность
- Устойчивость к флейкам
- Отчёты и CI
